Config Control Report

Functional report for the Config screen in TestUtilApp. This control edits application settings through a dark themed PropertyGrid and persists them to config.json.

Control: ConfigControl UI: WinForms PropertyGrid Config: AppConfig + ConfigService Updated: 2026-05-31

Purpose

ConfigControl is the application's central settings editor. It exposes the current AppConfig object in a PropertyGrid so the user can inspect and edit model paths, confidence thresholds, file-filter settings, last-used paths, and inspection options.

The screen is designed for direct operator configuration rather than a guided workflow. It uses a larger font size, a widened value column, and a persistent log/status area to make config edits easier to review.

Main Files

File Role
TestUtilApp/Form/ConfigControl.cs Runtime behavior, config loading, saving, reload, PropertyGrid events, DICE path Enter-save support, and log output.
TestUtilApp/Form/ConfigControl.Designer.cs Layout for the title bar, Save/Reload/Open Folder buttons, PropertyGrid, log panel, and status panel.

UI Structure

Area Description
Top command bar Displays the title and the available commands: Save, Reload, and Open Folder. The old Reset command has been removed.
PropertyGrid Shows the expandable AppConfig tree. The left property-name column is adjusted to about 30%, leaving about 70% for values.
Log panel Shows user actions, setting changes, load/save results, and DICE path guidance.
Status panel Shows the active config path, project root config path when available, and save/reload status messages.

Activation Flow

  1. OnActivated() runs when the screen becomes active.
  2. LoadConfig() binds the current AppConfig instance to the PropertyGrid.
  3. The PropertyGrid expands all items with ExpandAllGridItems().
  4. The PropertyGrid internal splitter is moved so property names use about 30% of the grid width.
  5. The status label displays the execution config path and, when available, the project root config path.
  6. The log records that the settings screen has been activated and loaded.

Commands

Command Behavior
Save Asks for confirmation, then saves the current AppConfig through ConfigService.SaveConfig().
Reload Warns that unsaved changes will be lost, reloads settings through ConfigService.LoadConfig(), and rebinds the PropertyGrid.
Open Folder Opens the folder containing the active execution config.json in Windows Explorer.
Current design: Reset is intentionally not available in this screen.

DICE Model Path Editing

The Path property in each DiceModelSetting supports two editing methods.

  • Click the PropertyGrid's default ... button to open FolderBrowserEditor and select a model folder.
  • Type a path manually in the Path value cell, then press Enter to commit and save the value.

The Enter-save behavior is implemented by listening for KeyDown events inside the PropertyGrid and checking whether the selected row is a DICE model Path item. 

if (e.KeyCode == Keys.Enter && IsDiceModelPathGridItem(propertyGridConfig.SelectedGridItem))
{
    CommitAndSaveDiceModelPathEdit();
}
Implementation note: The PropertyGrid's edit commit and splitter movement use reflection against the internal PropertyGrid view. This keeps the UI compact, but it should be checked if the WinForms runtime is upgraded.

Persistence

ConfigService manages two config locations when possible.

  • Execution folder config: the config next to the running executable.
  • Project root config: the source project config.json, detected from a bin path.

When saving, the execution config is written first. If the project root config path exists, it is also updated. This keeps Visual Studio debugging and source config editing aligned.

Validation And Feedback

  • All save, reload, and open-folder operations are wrapped in error handling.
  • Failures are displayed in a message box and written to the log.
  • Successful saves update the status label with a timestamp.
  • Property changes are logged through PropertyValueChanged.

Current Limitations

  • The PropertyGrid's built-in ... editor button appears only when the row is active. A custom always-visible overlay button was avoided because row alignment can drift during scrolling.
  • Some setting changes may require feature reactivation or model reload to affect already-loaded runtime models.
  • The PropertyGrid is a generic config editor, so workflow-specific screens still provide the more ergonomic controls for common operations.
